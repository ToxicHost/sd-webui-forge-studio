# Phase 8 — Public Beta and Upstream Operations

## Purpose

Prove the project can be supported and updated, not merely launched once.

## Steps

1. Complete at least two upstream merge rehearsals.
2. Recruit a small hardware/model test group.
3. Collect safe diagnostics.
4. Verify performance on at least two machines.
5. Triage bugs by blocker/high/medium/low.
6. Publish known limitations.
7. Run release-candidate soak.
8. Test emergency rollback.
9. Publish contribution/support/security process.
10. Decide stable support matrix.

## Exit criteria

- no blocker correctness issues;
- upstream sync process works;
- beta testers can install and report diagnostics;
- performance claims reproduce;
- `0.9.0-beta` candidate.
